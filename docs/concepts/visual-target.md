# 视觉目标卡 · 护理缺陷整改闭环系统

> 本轮运行环境不具备图像生成能力，故**只提供结构化视觉目标卡**，不生成概念图、不放占位图。
> 真实运行截图见 `docs/screenshots/`（由执行阶段采集）。

---

## 一、交付形态

**桌面常驻小工具**：Electron 主进程（系统托盘常驻 + 窗口 + 开机自启）承载运行时，
渲染进程承载窗口界面。**不对院内暴露对外监听端口**。
运维与排障通道为 CLI（`doctor` / `replay` / `export`）。

因此「视觉目标」的载体是**浏览器界面（Electron 渲染进程）**与**终端会话**，
不是命令行表格。

---

## 二、三个状态

### 状态 1 · 起始态（应用刚起来，还没拉到上报）

窗口顶部是页头区（标题「护理缺陷整改闭环」+ 一句说明 + 主操作「立即巡检」），
页头右侧两个数字块：**在办 0** / **超期 0**。
中部三栏：左栏「在办列表」显示**空态**——一个图标 + 一句说明
「还没有收到新的护理缺陷上报」+ 一行行动入口「立即巡检」；
中栏「步骤时间线」与右栏「确认与回写」是灰态占位（等选中一件后才有内容）。
底部是运行摘要条：巡检 0 次 / 重试 0 次 / 模型调用 0 次 / 估算成本 未配置单价。

### 状态 2 · 首个可用瞬间（一条上报刚到，处置单已建、停在「待分级」）

左栏在办列表出现第一张卡片：
**上报单号 / 病区 / 班次 / 当前步「待分级」/ 停留时长 03:12**，
当前步用**待办色**（琥珀）标签，超期时用**超期色**（砖红）标签。
中栏时间线出现两段：第 1 段「要素抽取」已完成（耗时 1.4s，系统），
第 2 段「等待护士长分级」——**这是单独的等待段**，标出已等待 03:12，
让护理部一眼看出**卡在等人**而不是卡在系统。
右栏确认区显示：模型给出的分级草稿（**标着「草稿」**）+ 依据原句（叙述中被高亮的原句）
+ 规则校验结论；底部「回写质控系统」按钮**处于禁用态**（灰底、不可点），
旁边一行小字说明「需先确认分级」。

### 状态 3 · 成形态（跨天、多件在办、已销号、超期催办中）

左栏按状态分栏（待分级 / 措施待复核 / 待销号 / 已闭环），
每栏顶部是分栏计数，栏内卡片带筛选（病区 / 停留时长 / 是否超期）与分页。
中栏时间线展开为完整分段：要素抽取 → 分级（护士长 王护士长 确认）→ 措施 → 复核 → 销号，
段与段之间的等待段独立呈现并标时长，**点击某步可在右栏跳到对应确认项**。
右栏显示销号确认与**回执号**（receipt_id），与导出台账同一数据源。
底部运行摘要：巡检 12 次 / 重试 2 次 / 模型调用 37 次 / 估算成本 ¥1.86。
页头超期数字变为红色，台账导出按钮可用。

## 三、视觉语言

### 配色（设计 token，不依赖系统深浅色——院内机器主题不可控）

| 用途 | 色值 | 说明 |
|------|------|------|
| 品牌主色 | `#1F6FEB` | 页头主操作、选中态描边 |
| 成功 / 已闭环 | `#1A7F5A` | 闭环标签、校验通过 |
| 待办 / 等待中 | `#B7791F` | 当前步「待分级」、等待段 |
| 超期 | `#C0392B` | 超期标签、超期数字 |
| 失败 / 错误态 | `#B42318` | 错误提示、重试耗尽 |
| 中性-背景 | `#F5F7FA` | 页面底色 |
| 中性-卡片 | `#FFFFFF` | 卡片 / 面板底色 |
| 中性-描边 | `#E3E8EF` | 分割线、表格线 |
| 中性-正文 | `#1F2733` | 正文 |
| 中性-辅助 | `#6B7684` | 辅助说明、停留时长 |

### 字体层级

系统中文栈：`-apple-system, "PingFang SC", "Microsoft YaHei", "Source Han Sans SC", sans-serif`。

| 层级 | 字号 / 行高 | 字重 | 用途 |
|------|-------------|------|------|
| 页头标题 | 20px / 28px | 600 | 页面标题 |
| 区块标题 | 16px / 24px | 600 | 栏标题、面板标题 |
| 正文 | 14px / 22px | 400 | 列表项、描述 |
| 辅助文字 | 12px / 18px | 400 | 停留时长、字段说明 |

数字（停留时长、在办数、token 用量、成本）统一 `font-variant-numeric: tabular-nums` 等宽对齐。

### 版式与密度

- 间距走 **8px 栅格**（4 / 8 / 12 / 16 / 24 / 32）。
- 三栏布局：左栏固定 320px（列表）、中栏自适应（时间线）、右栏固定 400px（确认区），
  中栏与右栏之间 1px 描边分隔，不靠阴影堆叠。
- 留白密度偏紧：卡片内边距 16px，卡片之间 12px，栏之间 24px —— 桌面常驻工具要一屏看全。
- 圆角分三级：卡片 8px / 标签 4px / 模态 12px。

### 信息层级

1. **当前步与停留时长**（一眼要看的地方）——列表项左侧色条 + 加粗；
2. **可执行的下一步**（确认按钮 / 巡检按钮）——主色实心，每屏只有一个 primary；
3. **依据与结论**（草稿、原句、规则结论）——右栏，正文 14px + 辅助 12px；
4. **运行摘要**——底部一行 12px 辅助文字，不抢主视线。

## 四、必须可达的约束（只允许用当前依赖真能做出来的元素）

- ✅ 纯 DOM + CSS（设计 token 用 CSS 变量）——**依赖里没有 UI 框架**，不引入组件库。
- ✅ 骨架屏 = CSS 渐变占位块；toast = 原生 DOM + CSS transition（150–250ms）。
- ✅ 图标用**内联 SVG**（lucide 风格路径），**不用 emoji**。
- ✅ 时间线 = 普通 DOM + CSS 定位条（宽度百分比由纯函数算出）。
- ❌ 不画 WebGL / 3D 场景、不做复杂动画库、不做花哨图表（时间线条是纯 CSS 宽度比例）。
- ❌ 不依赖系统深浅色主题（院内机器不可控），语义色一律由 token 定义。
- ⚠️ 待确认按钮的**禁用态必须真实可见**：灰底 + 禁用光标 + 旁边一句「需先确认分级」。
